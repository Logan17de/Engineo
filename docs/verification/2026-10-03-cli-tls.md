# Engineo application CLI: isolated HTTPS transport acceptance

## Result and scope

The corrected built application CLI passed this focused TLS suite on 2026-10-03:
**15 tests passed, 0 failed, 0 skipped**, comprising 14 subtests and their parent.
The recorded run took **1613.813298 ms**. This is a local socket acceptance result,
not CI, publication, production readiness, real identity provisioning, database
acceptance, GUI acceptance, or a claim about an entire committed source tree.

The test-only deliverable is `packages/cli/test/tls.test.mjs`. It starts isolated
synthetic HTTPS services on OS-assigned `127.0.0.1` ports and executes the existing
`packages/cli/dist/main.js` as real Node subprocesses. It never imports or mocks
the client's transport. The fixture's `/auth/me` and project responses are
synthetic; server-side authentication and persistence belong to the separate real
API/database acceptance suite.

No CLI/API source, CLI package scripts, CI, dependencies, network settings, OS or
browser trust stores were edited by this deliverable. No real credential, real
service, PostgreSQL instance, package install, network audit, deployment, or
publication was used.

## Observed coverage

- Default trust rejects the disposable CA with `transport_failed` / exit 8 and
  zero HTTP requests, including zero authentication or project requests
- Explicit `NODE_EXTRA_CA_CERTS` supplied only to a disposable CLI child permits
  normal verified HTTPS to `localhost`; the complete validated configuration
  snapshot is returned successfully
- The intended service receives the fixture cookies, immutable session header,
  explicit Origin, and encrypted TLS 1.2/1.3 requests; `/auth/me` precedes project
  I/O
- A subsequent child without that CA still rejects the same service, showing the
  test did not change shared trust
- The same CA-trusted certificate, whose SAN is only `DNS:localhost`, is refused
  for `https://127.0.0.1`, with zero additional HTTP requests
- A different actor or session in `/auth/me` returns `identity_mismatch` / exit 5
  and never reaches a project route
- An HTTPS 302 from `/auth/me` returns `redirect_refused` / exit 8 before any
  project request or connection to the redirect target
- HTTPS 307 and 308 responses from an authoritative-validation POST return
  `redirect_refused` / exit 8; the original POST carries CSRF, but neither a
  redirected POST nor any session/CSRF credential reaches the target
- A calibrated test-only DNS/TCP observer records attempted connections on a
  private IPC descriptor and prevents actual external traffic if a regression
  attempts it; its calibration covers TCP, callback DNS, and promise DNS
- `NODE_TLS_REJECT_UNAUTHORIZED=0` is refused as
  `insecure_tls_environment` / exit 2 before any DNS/TCP attempt, HTTP request, or
  TLS warning
- Default loopback HTTP without its explicit development flag returns
  `https_required` / exit 2 before dial
- Non-loopback `http://192.0.2.1:43123` remains `https_required` / exit 2 even with
  `--allow-http-loopback`; the observer reports zero DNS/TCP attempts
- URL parser aliases `127.1` and integer IPv4 remain `invalid_arguments` / exit 2
  before dial
- Every CLI invocation must emit exactly one versioned JSON line, a matching OS
  exit status, and empty stderr, without the fixture session/CSRF values or any
  certificate/private-key PEM bytes

The no-dial preload is confined to pre-network rejection cases and its own
calibration. All HTTPS success, trust, hostname, identity, and redirect cases use
the unmodified built Node transport without that preload.

The final recorded counts were **9 source HTTP requests**, including **3 project
requests**, **10 source TCP connections**, and **7 completed secure connections**.
The redirect target received **0 TCP connections and 0 HTTP requests**. Counts
are observations of this run, not a fixed TCP-pooling requirement.

## Private, disposable certificate/session handling

Already-installed OpenSSL generates a fresh one-day test CA and server leaf on
each opted-in run. The certificate is CA-signed and hostname-constrained; no
insecure verification switch is used. Fixture session/CSRF values are newly
generated random strings, used only by the synthetic service.

The CA, CA key, leaf key, certificate, CSR, explicit auth JSON, configuration, and
no-dial preload exist only in a private temporary directory outside deliverable
and evidence paths. That directory is mode 0700; fixture files are mode 0600.
The test closes both services and removes the directory in `finally`, then checks
that its path no longer exists. The recorded run verified removal. No CA, key,
auth JSON, credential value, or private fixture path appears in the evidence.

The child environment deliberately excludes inherited Node option, CA, system
trust, and SSL settings. Adding a fixture CA to a child does not disable ordinary
certificate-chain or hostname verification. No OS/browser/user trust or network
setting is changed. Socket permission denial is a hard test failure; it is not
worked around through another route.

## Reproduction and static checks

Prerequisites: existing Node 24+ and OpenSSL, a previously built application CLI
with its paired contracts runtime, and permission for ephemeral loopback sockets.
The suite installs nothing and requires no PostgreSQL or Rust executable.

After integrating the test into the CLI checkout:

```sh
ENGINEO_CLI_TLS_TEST=1 node --test --test-reporter=tap packages/cli/test/tls.test.mjs
```

For the isolated deliverable against the frozen corrected build:

```sh
cd /workspace/shared/engineo-cli-tls-tests
ENGINEO_CLI_TLS_TEST=1 \
ENGINEO_CLI_TLS_ENTRY=/workspace/shared/engineo-headless-cli/packages/cli/dist/main.js \
node --test --test-reporter=tap packages/cli/test/tls.test.mjs
```

Without explicit `ENGINEO_CLI_TLS_TEST=1`, the test reports one skip and starts no
fixture services. That default skip was checked separately and is not counted as
a pass. This increment does not edit package/CI scripts; their owner can add the
opted-in test command where intended.

Static checks passed against the final test source:

```sh
node --check packages/cli/test/tls.test.mjs
/workspace/shared/engineo-headless-cli/node_modules/.bin/biome check \
  --config-path=/workspace/shared/engineo-headless-cli/biome.json \
  packages/cli/test/tls.test.mjs
```

The captured tools were **Node v24.19.0** and **OpenSSL 3.5.7**. Biome checked one
file with no changes required. Evidence contains the actual TAP run and static
output, plus the exact before/after runtime/test manifests. The TAP file SHA-256
