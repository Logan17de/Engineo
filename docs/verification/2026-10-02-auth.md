## Verified failure/security behavior

- Independent source and normalized-account quotas; no email-rotation bypass.
- Atomic counters across instances, saturation, expiry and active-bucket preservation.
- Malformed JSON consumes source quota before parsing; forged forwarding headers
  do not change source identity; IPv6 /64 and mapped IPv4 normalization tested.
- Limiter database stages cap admission at 16; password/session stages cap at four.
  A held table lock with 20 concurrent HTTP requests returns 503 within the
  server-side lock deadline, emits no cookies and recovers on retry.
- Shared cleanup fails closed, immediately retries failures, and advances its
  next successful deadline only after completion.
- Missing limiter storage rejects before authentication; errors expose no SQL.
- Real audit-trigger failures roll session creation/revocation back. Login emits
  no cookie on failure; logout preserves its session for retry; a retry produces
  exactly one logout audit event.
- Admin/owner project-ID substitution across tenants is denied by authorization.
- Fixed attacker session values are replaced; CSRF, revocation and MFA-required
  blocking remain tested. Invalid stored scrypt parameters fail closed.

## Security-gate changes

JavaScript and Rust dependencies are locked; CI installs frozen/locked inputs.
A dependency-review job rejects newly introduced high/critical vulnerabilities in
runtime, development and unknown scopes. No repository settings were changed.
CodeQL now runs on stacked draft PRs too, retains SARIF evidence for seven days,
and fails on security severity >=7 or error-level results. No finding is suppressed.

Active-key storage under a distributed flood, idle pseudonym retention, customer
ingress sizing, production reverse-proxy trust, deployment encryption and high-
privilege MFA provisioning remain explicit operational gates in `ACCEPTANCE.md`.
