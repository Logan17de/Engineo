# Engineo frozen configuration backup/restore drill

Passed on 2026-10-03, 10:46:41–10:46:49 UTC. This is a disposable local logical recovery check using synthetic fixtures, not a production recovery certification.

## What was verified

- A fresh, uniquely named source database received the five immutable migrations. The restore target was created from template0 and had zero public tables; no migration was applied to it before restore.
- PostgreSQL 17.11 custom-format pg_dump/pg_restore preserved every public table: 21 tables, 2,045 rows, exact table counts and SHA-256 row inventories. Table columns, constraints and validation, indexes, and enabled triggers also matched.
- The fixture included two synthetic users and sessions, one tenant/project, 1,000 activities, 999 relationships, a completed real Rust calculation, and four retained configuration reviews: applied, no-op, cancelled, and pending. Three terminal receipts were present in the dump.
- All five migration checksums, native relationship IDs/tuples/creation timestamps, compact plan/outcome data, retained heavy artifact hashes, generated byte counts, and global/project accounting counters matched after restore.
- The four primary review artifacts totaled 5,280,748 logical UTF-8 payload bytes. Both counter hashes and independent sums/counts agreed; this is not a physical storage size measurement.
- The restored API authenticated using the restored session records. Exact current configuration, calculation result and provenance, pending review, and the project’s .123/.456/.789 setting instants were preserved.
- Historical receipt reads, original plan-request replay, applied/no-op apply replay, and cancelled cancel replay returned the original terminal evidence without duplicate outcomes. Cancelled apply returned the expected conflict; a restored viewer could not apply a review.
- The review that was pending at backup applied once after restore, advancing revision 3 to 4. Replay returned the same receipt. The old calculation remained exact immutable history, while the current result correctly became unavailable for the changed input. Surviving relationship identity remained unchanged.
- A separate target-only maintenance fixture inserted 65 valid, short-retention reviews with all triggers enabled. After real elapsed retention expiry, three maintenance calls removed 64, then 1, then 0 artifacts. Counter hashes and independent aggregates remained valid after each call; compact plans, outcomes and audits remained unchanged. Direct counter tampering and deletion of still-live primary artifacts were rejected.
- The existing engineo database’s migration ledger SHA-256 remained unchanged. The frozen 20-file manifest, its source files, and compiled API/contracts files remained unchanged. No repository edits or publication occurred.
